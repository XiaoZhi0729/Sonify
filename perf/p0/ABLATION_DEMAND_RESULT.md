# 选项1（按需录制）进入场景消融：有真收益（2026-10-24）

按裁决先做进入场景消融，不拿滚动场景的数硬套。结论：**有真实的帧时间收益**，
值得推进行为级改动，具体数字如下。

## 1. 实现（消融最小版）

- `rememberTitleBackdrop` 的 onDraw 改为：`TitleBackdropSampleDemand > 0` 才 `drawContent()`，
  否则只画页面底色。
- `TitleBar` 在 `barVisible`（顶栏背景出现）期间登记需求。
- 弹层登记这次**没做**（进入场景不涉及弹层），正式实现必须带上
  （`LiquidDropdownLayout` 展开期间登记），否则列表中部的行尾 ⋮ 菜单玻璃会采空。
- 消融包 sha256 `8b0e0faeeba4a4390b8b94a10950493ecf8047676b0128c817ce8f2548d48e3b`。

## 4. 判读与边界（如实）

1. 收益只出现在**顶栏隐藏期间**（进入动画 + 页面停在顶部）。用户开始滚动、顶栏出现后
   恢复全量录制，滚动场景收益为零——这是设计使然，不是缺陷。
2. 行为级影响面：顶栏隐藏时 backdrop 只含页面底色。顶栏隐藏时其玻璃材质本身
   `glassBackdropAlpha=0`（不可见），理论无视觉差异；但**正式实现前必须做一轮
   静止/滚动/弹层三态的截图比对**（尤其歌手页、专辑页这类按钮常驻的页面）。
3. 消融实现缺弹层登记，正式实现必须补（上一轮已验证过该机制的代码，可直接复用）。
4. 本轮数据来自 39.7°C 热机，绝对值偏 pessimistic，配对差可信。

## 5. 建议

批准行为级改动，正式实现 = 本消融 + 弹层登记（上轮已写过的 `TitleBackdropRecordDemand`
机制）+ 三态截图验证 + ABBA 配对回归（判据四项不变）。预期进入歌单 miss3 降 ~19pp、
p50 降 ~1.3ms，滚动场景不退化。
